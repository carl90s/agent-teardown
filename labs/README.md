# AI Agent 教学实验包（离线可运行）

配套中文书《深入理解 AI Agent：设计原理与工程实践》（李博杰）的动手实验。

**特点：零网络、零第三方依赖（除已装好的 numpy）、零 API key。** 所有"模型"都用教学替身模拟，
重点是把书里的概念变成能亲手跑、能看见数字、能故意改坏的代码。

## 0. 零环境配置：怎么跑

**最省事**：回到上一级目录，双击 `开始学习.cmd`，按 `3`–`8` 直接跑对应实验。
那个启动器会自动找到本机的 Python（并检查 numpy），你什么都不用配。

**手动跑**（任意一个装了 numpy 的 Python ≥3.10 都行）：

```powershell
$env:PYTHONIOENCODING="utf-8"          # 让中文输出不乱码（重定向到文件时尤其需要）
cd <这个目录>
python lab1_react.py
```

如果没有 `python` 命令，把 `python` 换成你自己解释器的完整路径即可，例如：

```powershell
& "C:\path\to\python.exe" lab1_react.py
```

> Windows 上如果直接双击 .py 发现中文乱码，先执行 `chcp 65001`（切到 UTF-8 代码页）再跑。

几个常见问题：

- **用哪个 Python？** Python ≥3.10 且装了 numpy 即可；本机实测是 **Python 3.12.14 + numpy 2.3.5**。
- **要按顺序跑吗？** 不用。`lab1`…`lab6` 都是独立脚本，`mockllm.py` 是同目录的公共库、自动导入。
- **为什么没有图？** 环境里没有 matplotlib，所有图表（柱状图、折线图）都用 ASCII 字符画。
- **要花多少钱？** 0。所有"模型调用"都是本地规则，账单数字是模拟出来的（但口径和真实服务商一致）。
- **退出码 0 且没有 Traceback** = 这个实验的所有断言都通过了（每个 lab 末尾都有 assert 自检）。

## 3. 公共库 `mockllm.py`：教学替身

真实 Agent 的循环是：**组装上下文 → 模型决策 → 执行工具 → 结果回填 → 再决策**。
这个循环跟"模型是谁"没关系，所以实验里用规则驱动的替身，行为和真模型完全同构：

```python
from mockllm import MockLLM, count_tokens
llm = MockLLM(policy="normal")
decision = llm.chat(messages, tools)     # 返回 {"reasoning", "content", "tool_calls"}
```

- 返回结构与真实 LLM API 一致（`reasoning` / `content` / `tool_calls`），**换成真 API 只需替换 `chat()`**。
- `count_tokens(text)`：中文 1 字 ≈ 1 token，英文/数字 4 字符 ≈ 1 token（BPE 的粗略近似）。
- 7 种 `policy` 是专门用来"故意弄坏"上下文的：`normal` / `no_tool_defs`（看不到工具）/
  `no_reasoning`（没有思考过程）/ `no_history`（只看最后一条）/ `no_tool_result`（结果不回填）/
  `hallucinate`（编造工具）/ `loop`（陷入重复）。

## 4. 每个实验：怎么跑 / 预期看到什么 / 思考题

### lab1_react.py —— 亲手跑一遍 ReAct 循环

- **概念**：一轮 Agent 的上下文是「静态前缀（系统提示词 + 工具定义）+ 动态轨迹（用户消息 / 模型回复 / 工具结果）」。模型每轮只看得到当前上下文。
- **任务**（书里图 1-4 的多币种收入汇总）：Q1 $2.5M、Q2 €2.1M、Q3 £1.8M、Q4 ¥380M → 年度总收入 + 季度均值。
- **预期看到**：静态前缀 **335 tokens**（系统提示词 125 + 工具定义 210）；第 1 轮并行发起 3 个
  `convert_currency`（EUR/GBP/JPY → USD）；第 2 轮用 `code_interpreter` 求和；
  第 3 轮给出 **年度总收入 $9,602,895.73，季度平均收入 $2,400,723.93**；最后美化打印完整 trajectory。
  （书中图 1-4 的中间结论 7,061,089.71 只算了 Q1~Q3，脚本里有注释说明差异。）
- **思考题**：① 如果工具定义有 200 个，静态前缀会占多少 token？② 为什么换算是并行发三个工具调用，而不是三次循环？

### lab2_ablation.py —— 复现书中实验 1-1：上下文消融

- **概念**：上下文决定 Agent 能看到什么，Agent 只能基于看到的信息决策。逐个抽掉要素，看它怎么坏。
- **预期看到**：文本表格 5 行（与书中图 1-3 一一对应），另有 2 行拓展配置：

  | 配置 | 轮次 | 工具调用 | 与书中结论 | 现象 |
  | --- | --- | --- | --- | --- |
  | 完整基线 | 3 | 4 | ✓ 成功 | 正常给出正确答案 |
  | 无工具定义 | 1 | 0 | ✓ 失败 | 看不到工具，只能凭常识瞎估 |
  | 无思考过程 | 6 | 5 | ✓ 部分成功 | 一次只换一个币种、还漏算 JPY |
  | 无历史记录 | 8 | 24 | ✓ 部分成功 | 同一批换算反复做，撞轮次上限 |
  | 无工具结果 | 8 | 24 | ✓ 失败 | 结果没回填，盲目循环 |
- **思考题**：① 为什么"无历史记录"和"无工具结果"表现相似、但"轨迹里的结果数"完全不同（24 vs 0）？
  ② 这五种缺失里，哪一种在真实产品中最常见？

### lab3_prefix_cache.py —— 前缀缓存的成本账

- **概念**：模型每读一个 token 都要算 KV；前缀逐字节相同才能复用（Prompt Cache）。
  中间任何一个字节变了，**从变的位置往后全部作废**。
- **预期看到**：同一个 20 轮会话，只改"上下文怎么拼"，账单差 5 倍以上：

  | 策略 | 命中率 | 成本 | 相对 A |
  | --- | --- | --- | --- |
  | A 静态前缀稳定 | **91.3%** | $0.005310 | 1.00x |
  | B 前缀里插时间戳 | 3.3% | $0.029041 | 5.47x |
  | C 历史重排/重写 | 22.9% | $0.023591 | 4.44x |
  | D 工具 schema 追加到**末尾** | 71.2% | $0.010740 | 2.02x |
  | E 工具 schema 插在历史**中间** | 3.3% | $0.029021 | 5.47x |

  D 与 E 是同一个变体讨论的两面：**动态加载工具 schema 没问题，关键是加在末尾**（对应书中 2.3 节
  提到的 2026 年生产框架做法）。
- **思考题**：① 确实需要带当前时间，放在哪里既满足需求又不打掉缓存？② 每轮都要检索知识库，检索结果该放哪？

### lab4_compress.py —— 上下文压缩策略对比

- **概念**：长会话的轨迹会撑爆窗口，压缩必有损；而**隔离**（把子任务丢进独立上下文，只回传结论）可以无损。
- **预期看到**：62 条消息、原始 **2139 tokens** 的排查轨迹，4 种策略的对比表：

  | 策略 | 压缩后 token | 压缩率 | 关键信息保留率 | 后续任务成功率 |
  | --- | --- | --- | --- | --- |
  | 滑动窗口（留最近 12 条） | 474 | 22.2% | 1/8 = 12% | 1/3 = 33% |
  | 摘要压缩 | 658 | 30.8% | 4/8 = 50% | 2/3 = 67% |
  | 分层压缩（远期要点+中期摘要+近期原文） | 1229 | 57.5% | 7/8 = 88% | 2/3 = 67% |
  | 子 Agent 隔离 | **232** | **10.8%** | **8/8 = 100%** | **3/3 = 100%** |

- **思考题**：① 分层压缩丢了哪一条关键信息（提示："修复方案"）？② 隔离的代价是什么（子 Agent 也要花钱、结论要不要信）？

### lab5_bm25.py —— 从零实现 BM25，以及混合检索

- **概念**：`score(q,d) = Σ_t IDF(t)·f(t,d)·(k1+1) / (f(t,d) + k1·(1-b+b·|d|/avgdl))`，
  `IDF(t) = ln(1 + (N-df+0.5)/(df+0.5))`：**k1 控制词频饱和，b 控制长度惩罚**。
- **预期看到**：9 篇中文 Agent 主题短文（ReAct / KV Cache / RAG / MCP / 压缩 / 记忆 / 多 Agent / BM25 / 工具调用）。
  ① 关键词查询排名正确（BM25 得分 31.99 排第一，assert 检查）；② k1/b 四种设置对照表（目标文档恒第一）；
  ③ 稠密替身 A（字符 bigram TF-IDF）**换个同义说法就吃零分**；④ 构造的查询
  「一群智能体如何分工配合，怎样让彼此不打架」下 **BM25 最高分 0.0000（全失明）**，
  概念向量替身 B 把《多 Agent 协作》排第一，融合后修回正确答案。
  实验 4 还特意演示反面教材：对"一路全零"的排名做 RRF，会把 `np.argsort` 的任意顺序当信号而排错。
- **思考题**：① k1 调大、b 调小分别让哪类查询变好？② 中文改成单字切分，排名会怎么变？
  ③ 0.5:0.5 这个融合权重，你会用什么办法定下来？

### lab6_eval.py —— Agent 评估：能力上限与业务可靠性

- **概念**：`Pass@k = 1-(1-p)^k`（k 次里**至少一次**成功 = 能力上限）；
  `Pass^k = p^k`（k 次**全部**成功 = 业务可靠性）。p=0.9 时两者在 k=1 相等，然后迅速分道扬镳。
- **预期看到**：① 蒙特卡洛 **20000 次**验证解析公式，十个 k 的最大误差 **0.0050**（<1 个百分点）；
  ② ASCII 折线图：Pass@k 冲向 1.0，Pass^k 在 k=10 时掉到 **0.3487**；
  ③ Wilson 95% 区间：90/100 vs 88/100 的 2% 差距 **z=+0.45 不显著**（区间重叠），
  样本放大到 10000 才 **z=+4.52 显著**；要把 2% 的差距测出来每组需要约 **3528** 题；
  ④ Judge 偏差：位置偏差让同一对答案在两个顺序下胜率 65.6% / 33.7%（翻转率 56.4%），
  交换位置取平均后回到 **49.6%**；长度偏差让长答案胜率 **67.0%**，控制长度后回到 **50.8%**。
- **思考题**：① 一个"平均成功率 90%"的 Agent，让它连续独立做 10 次全对，概率是多少？这解释了产品里的什么现象？
  ② 位置偏差和长度偏差还有哪些偏差是"交换位置"治不了的？

## 5. 教学替身与真实场景的差别（诚实说明）

| 替身 | 真实场景 |
| --- | --- |
| `MockLLM`：规则 + 模板 | 真模型 API；把 `chat()` 换成 API 客户端即可，上下文组装逻辑不变 |
| 摘要压缩：抽取式（留含数字/关键事实的行） | 一次 LLM 生成式摘要 |
| 稠密替身 A：字符 bigram TF-IDF | 真正的嵌入模型 + 向量库（bge / text-embedding-3 等） |
| 稠密替身 B：手工概念向量表 | 同上；本实验用它把"语义"这件事变得可解释、可离线复现 |
| 分词：中文按相邻两字 bigram | 真分词器（BPE / SentencePiece / jieba 等） |
| 计费：命中 $0.1/M、未命中 $1/M | 以服务商实际价目为准（本实验只看相对倍数） |
| 评估：蒙特卡洛假定每次试验独立同分布 | 真实评估还有题目难度分布、模型自一致性、采样温度等 |

**一句话总结这套实验想让你记住的事**：
上下文是 Agent 唯一的输入（lab1/lab2），它的字节布局直接决定账单（lab3），
它会被压缩、也可以被隔离（lab4），检索决定了模型能看到什么（lab5），
而"看起来差不多"的两个指标，在统计上可能是天壤之别（lab6）。
